# 对话意图与用例工作区：实现与验收

日期：2026-09-28。本次实现基于能力评审报告，覆盖意图、目标解析、分析报告和任务状态映射。

## 已实现

- 新增独立意图：用例评审、冗余检查、覆盖分析。生成、修改、删除、查询和知识问答继续保留。
- 区分“检查刚生成的用例”“补充覆盖缺口用例”“如何检查冗余”等读、写和知识问题。
- 服务端逐操作解析目标。本轮明确编号/标题/模块优先于旧选择；支持模块完整路径、唯一模块名称及后代模块。
- 未知编号、未知模块、重名模块不静默回退到旧选择；复杂排除范围要求重新选择。
- 查询遵守模块与优先级范围，移除固定前 20 条截断。目标目录和正式用例上下文使用批量读取。
- 优先级赋值与筛选分开处理：“把 P1 用例改为 P0”筛选 P1，不以 P0 作为旧值条件。
- 评审、冗余和覆盖任务读取实际用例，生成包含严重程度、用例引用、依据、建议和限制的结构化报告；拒绝未知用例引用。
- 对话展示分析步骤、任务状态、检查数量与报告；报告提供定位用例按钮。
- 模块增量生成整理测试说明时传入已有用例上下文，要求结合已有覆盖规划新增内容。
- 工作区从服务端任务恢复目标与工作中状态；脑图/列表使用同一批解析后的用例 ID。维护阶段刷新也会恢复任务监听。
- 服务端确认的目标回写当前选择，避免应用后错误高亮旧选择；大范围选择分组持久化。
- 删除“重复/无效/过时”等尚未判定的用例时，不把整个模块直接作为删除清单。明确用例后仍通过现有差异确认执行。

## 验证与边界

- API 意图、范围及现有对话回归：73 项通过，包含 1000 条用例范围完整性。
- Agent 报告与生成流水线回归：21 项通过。
- 浏览器：任务恢复、脑图/列表映射、报告定位，以及原脑图搜索/键盘导航共 3 项通过；另补验旧选择不覆盖本轮明确编号。
- TypeScript、ESLint、Ruff 和前端生产构建通过。
- 此前浏览器测试使用受控 API 数据和模拟模型；本轮另在隔离的本地数据库、API、Worker 与 Web 中完成真实模型端到端验收，结果见下节。
- 当前不是任意条件查询引擎，也不承诺任意自然语言表达都正确；复杂指代和语义条件仍需进一步扩展与验收。
- 冗余报告不会自动合并/删除；没有新增批次回滚能力。自然语言候选删除与报告后自动修复编排尚未补齐。
- 修改位于本地工作区。新意图须同时更新 Web、API 和 Agent Worker；原有 3101 页面连接的远端 API/Worker 尚未部署本次代码。

验收入口：[独立本地工作区](http://localhost:3105/workbench/conversations/b676c568-572e-4e0e-b1ff-62b57674ae81)。该入口使用独立的本地 Postgres、Redis、API、Agent Worker 与 Web，不影响原有 3101 服务。集合初始包含 1000 条、20 个业务模块，每模块 50 条；生成后纳入 1 条，当前共 1001 条。
