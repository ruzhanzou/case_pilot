## 4. 验收步骤

### 4.1 登录

1. 打开 Web。
2. 使用示例账号登录。
3. 确认进入“用例资产管理”。
4. 确认空间名称为“体验用户的质量空间”。

通过标准：

- 无需调用 Mock 数据即可登录。
- 刷新页面后仍保持登录。
- 登录失败时显示明确错误，不进入工作台。

### 4.2 用例集合管理

1. 查看“账号登录验收用例集”。
2. 创建一个临时用例集合。
3. 编辑临时集合名称和说明。
4. 删除临时集合。

通过标准：

- 列表数量与数据库一致。
- 新增和修改刷新后仍存在。
- 删除后不再出现在列表中。
- 操作写入审计记录。

### 4.3 用例管理

1. 打开 `AUTH-001`，检查基本字段、前置条件、步骤和校验点。
2. 点击编辑，修改来源或任意非关键字段。
3. 保存为新版本。
4. 确认版本号从 V1 递增为 V2。
5. 在用例列表切换内容状态。
6. 新建一条临时用例，随后删除。

通过标准：

- 新建、查看、编辑和删除均调用真实 REST API。
- 编辑必须携带 `base_revision_id`；冲突返回 `409 revision_conflict`。
- 编辑产生新 Revision，不覆盖历史版本。
- 已通过用例再次修订时回到 Pending。
- 内容状态支持 Pending、通过、不通过、跳过和堵塞。

### 4.4 QA 执行

1. 点击左侧“执行用例”。
2. 确认执行队列加载当前集合全部用例。
3. 逐条勾选执行步骤。
4. 在未执行、通过、不通过、跳过和堵塞之间切换执行状态。
5. 填写实际结果。
6. 可选填写缺陷编号或链接。
7. 点击“保存执行记录”。
8. 刷新页面并重新进入执行页。

通过标准：

- 步骤勾选、执行状态、实际结果和缺陷引用刷新后仍存在。
- 执行状态不覆盖用例内容状态。
- 进度按“状态不再是未执行”的用例数计算。
- 执行记录使用创建时的用例 Revision；后续编辑用例不会改写历史执行内容。

## 5. 状态语义

| 用例内容状态 | 执行状态 | 含义 |
| --- | --- | --- |
| Pending | 未执行 | 用例内容待确认；本轮尚未执行 |
| 通过 | 通过 | 用例内容已确认；本次执行符合预期 |
| 不通过 | 不通过 | 用例内容未通过审核；本次执行与预期不符 |
| 跳过 | 跳过 | 用例内容或本次执行被主动跳过 |
| 堵塞 | 堵塞 | 用例内容或执行因外部条件无法继续 |

两套状态独立存储，不能互相覆盖。
