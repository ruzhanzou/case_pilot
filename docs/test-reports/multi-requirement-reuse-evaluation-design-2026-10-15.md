# 多需求生成、复用与工作区关联评测集

版本：1。设计日期：2026-10-15。数据集位于 `apps/web/e2e/fixtures/multi-requirement-reuse.json`。

每组独立注册测试账户并创建集合，防止上一组的历史资产影响下一组。模型使用实际配置的服务；数据库、队列、文件存储与日常环境隔离。测试不模拟网络响应。截图输入不在本轮范围。

## 样本矩阵

| ID | 业务与模式 | 历史来源 | 本次需求 | 直接复用 / 修改 / 新增 |
| --- | --- | --- | --- | --- |
| E01 | 青禾图书借阅，全新生成 | 无 | 正常借阅、5 本上限、库存为零 | 0 / 0 / 3 |
| E02 | 云杉购物车，回归补充 | 用例资产 | 加入商品、删除唯一商品、数量上限 10 件 | 2 / 0 / 1 |
| E03 | 星桥验证码，相似需求变更 | 用例资产 | 正常登录不变、有效期 5→2 分钟、60 秒发送限制 | 1 / 1 / 1 |
| E04 | 远山报销，相似需求变更 | Excel | 100 元报销不变、主管审批上限 1000→500 元、缺失票据拒绝 | 1 / 1 / 1 |
| E05 | 北辰会员积分，混合来源 | 资产与 Excel | 支付获积分不变、200 积分抵 1 元、余额不足拒绝 | 1 / 1 / 1 |
| E06 | 海岚优惠券，防止错误复用 | 名称相似的旧资产 | 满减门槛 500→800 元、800 元边界、过期拒绝 | 0 / 1 / 2 |

18 条需求均有稳定编号、原始规则及预期结果匹配模式。场景固定为每条需求一个测试点和一条候选，用于检查需求分离及关联完整性，不代表生产环境要求始终一对一。

## 验收门槛

1. **意图和规划**：输入形成一个生成任务；策略与场景一致；每组恰好三个测试点；复用决策与来源符合预期。
2. **内容**：直接复用的标题、操作和预期与历史快照一致；变更用例正文不得含过期规则；18 条需求的关键业务预期分别匹配独立候选。
3. **来源**：Excel 场景的历史来源为 Excel；混合场景同时出现资产与 Excel，不能把一种来源静默丢弃。
4. **关联**：已有正式用例可手动关联测试点、刷新后保留、点击可定位用例。候选采纳时按生成时的规划版本自动建立正式用例关联，所有生成测试点均可追溯。
5. **数据保护**：关联不修改正文；采纳不覆盖旧资产；错误空间、错误测试点、旧用例版本、旧规划版本被拒绝；重复关联幂等。
6. **版本语义**：仅修改复用选择的新规划继承关联；需求变化不自动继承；关联后用例修订，显示“版本已变化，需重新确认”。
7. **工作区**：规划展示已关联正式用例数量，采纳和刷新后不退回“尚未生成用例”；无浏览器运行时异常。

自动业务预期匹配只能发现选定的关键语义问题，不等同于人工评审或完整语义证明。结果中保留规划、候选与正式用例快照，支持人工逐条核验。

## 交互语义

关联与生成选择分开：关联表达可追溯关系，不自动证明覆盖正确，也不自动阻止生成。用户认定已有用例足够覆盖时，可将该测试点选择为“不纳入本次”。本轮手动关联范围为当前集合；跨集合资产通过生成流程检索复用。

关系存放于 `workspace_case_links`，绑定测试说明 ID（含版本）、测试点 ID、正式用例 ID、关联时的用例版本及来源。没有将不同规划的同名测试点合并，也没有改写已有用例正文。

## 运行

先在隔离数据库执行迁移并启动 API、任务队列和前端，环境配置复用现有模型连接，不写入测试数据集。随后设置：

```sh
CASEPILOT_REAL_ACCEPTANCE=1 \
CASEPILOT_E2E_BASE_URL=http://localhost:3015 \
CASEPILOT_E2E_API_URL=http://localhost:8015 \
pnpm --dir apps/web exec playwright test \
  e2e/multi-requirement-reuse.spec.ts e2e/planning-links-contract.spec.ts
```

可通过 `--grep E03` 只重跑指定样本。证据输出至 `output/multi-requirement-eval-20261015/`。每组保存规划、候选与正式用例、关联信息、时间与截图；失败保留浏览器 trace。运行报告与本设计分开，设计本身不表示验收已通过。

## 性能观测

记录每组规划耗时及从提交需求到采纳完成的总耗时。总耗时包括用户操作模拟、刷新和轮询，不能直接视为纯模型延迟。6 个单次样本仅用于发现异常波动，不推导 P95、吞吐上限或生产容量。

完成 E01、E02 后，还可运行 `e2e/planning-links-navigation.spec.ts`，复用已保存的测试账号与正式用例，验证“测试点 → 正式用例 → 原规划版本及测试点”的双向定位，不再次调用模型。
