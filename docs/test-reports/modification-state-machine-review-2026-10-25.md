# 自然语言修改流程重构与验收

分支：`codex/modification-state-machine`。独立 worktree，保留原 checkout 未提交修改。

## 设计

模型仅解释回复事件；`rewrite_state.py` 的纯状态处理器负责草稿更新、确认失效、澄清与执行门槛；数据库和队列副作用留在 API。草稿阶段为 collecting、clarifying、preview、executing、cancelled。后台运行、失败、采纳和拒绝继续以既有 ConversationOperation / GenerationJob / CaseChangeSet 状态为准，避免再建立一套互相矛盾的任务状态。

| 事件 | 转换 | 执行约束 |
| --- | --- | --- |
| 低置信度或含糊回复 | clarifying | 保留已知要求，清除旧预览 |
| 修改要求或范围 | collecting → preview / clarifying | 必须生成新预览 |
| 确认同时更改选择 | collecting | 不执行旧范围 |
| 单纯确认 | executing | 有预览、范围已解析、要求就绪且非空、无未解决问题 |
| 明确取消 | cancelled | 清除预览，保留取消状态 |
| 范围校验失败 | clarifying | 保存错误，刷新后确认仍不能绕过 |

范围选择继续独立校验资产权限、引用范围、编号和去重后的 requested_count。数量不符时澄清，不能自动扩大范围。大集合中无法表示的排序或前 N 条要求继续保守澄清。

## 修复

1. 只调整范围时，模型默认 requirements_ready=true 不能补造修改方向。
2. 旧预览不能覆盖当前草稿的未就绪状态；仅旧版本数据迁移允许恢复。
3. 范围失败的澄清信息持久化，防止再次确认绕过。
4. 更新后的范围同步到计划，避免残留旧 target_text。
5. 初始预览也建立草稿状态，取消时保存终止状态。
6. 工作区展示具体澄清问题，避免通用提示隐藏需要回答的内容。
7. 修复测试夹具：旧版任务显式移除 draft；语义模拟对象补全 continue_cases；浏览器夹具支持普通 messages 路由和显式 resume 路由。
