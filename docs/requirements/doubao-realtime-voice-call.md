# 豆包 App 实时语音通话测试需求

> 需求编号：VOICE-REQ-20260728
> 用途：CasePilot 用例生成与用例管理端到端验收
> 平台：iOS、Android
> 需求状态：验收基线

## 1. 用户目标

用户从豆包 App 进入实时语音通话后，可以像自然对话一样持续说话、听取回答，并在豆包播报过程中随时插话。系统需要明确呈现“聆听、思考、回答、恢复中、已结束”等状态。

## 2. 功能范围

### 2.1 通话建立

- 用户点击实时语音通话入口后，系统检查登录态、网络和麦克风权限。
- 首次使用请求麦克风权限；拒绝或撤销后不得采集、缓存或上传音频。
- 连续点击入口只能创建一个有效会话。
- 建立成功后进入“聆听”状态，并显示系统麦克风使用提示。

### 2.2 双向实时交互

- 用户说话期间持续采集并上传音频流。
- 豆包依次呈现“聆听 → 思考 → 回答”状态。
- 豆包播报时用户插话，当前播报需要立即停止并切回“聆听”。
- 前后两轮字幕和音频不能重叠、乱序或重复。

### 2.3 音频路由

- 支持听筒、扬声器、蓝牙耳机和有线耳机。
- 路由变化时只允许一个输出设备工作。
- 耳机拔出、蓝牙断开后按系统策略回退到安全路由，不出现爆音、长时间静音或双路播放。

### 2.4 中断与恢复

- 覆盖弱网、断网、丢包、抖动、重连和服务超时。
- 覆盖来电、闹钟、音频焦点丢失、耳机插拔、切后台和锁屏。
- 恢复后不得重复提交用户语音或重复播放已完成回答。
- 无法恢复时必须结束会话并提供显式重试入口，不能无限显示“思考中”。

### 2.5 结束与隐私

- 用户主动结束或异常终止时，会话只结束一次。
- 立即释放麦克风、音频焦点、播放器和网络连接。
- 系统只按隐私策略保存允许留存的文本摘要，不保留未授权的原始音频。
- 新通话使用新的会话标识，不复用上一通话的音频缓存或未完成请求。

## 3. 验收阈值

| 指标 | 验收要求 |
| --- | --- |
| 首包音频 | 不超过 800ms |
| 端到端语音响应 | 不超过 1500ms |
| 弱网自动重连 | 不超过 3 秒 |
| 重复建连 | 同一用户操作只产生一个有效会话 |
| 资源释放 | 结束后麦克风提示、音频焦点和连接立即消失 |
| 状态一致性 | UI 状态、字幕、音频和服务端会话一致 |

## 4. 必须覆盖的测试维度

- 正常主流程
- 麦克风权限和隐私
- 用户插话与状态机
- 弱网、断网、重连与幂等
- 系统中断与后台策略
- 音频路由与设备兼容
- 时延与连续通话稳定性
- 结束后的资源释放与数据留痕

## 5. 开放问题

- 锁屏和切后台后是否允许继续保持实时语音通话？
- iOS 与 Android 的后台保活策略是否要求完全一致？
- 文本摘要默认保存多久，用户能否关闭保存？
