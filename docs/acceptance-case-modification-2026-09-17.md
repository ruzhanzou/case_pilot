# 用例修改端到端验收集合

## 范围与通过标准

从正式用例集合进入工作台，验证自然语言修改的目标识别、字段差异生成、人工审阅、应用或拒绝，以及对话、用例列表和脑图的一致性。每个场景使用独立的临时集合与两条正式用例，结束后清理测试资产。

| 编号 | 场景 | 验收点 |
| --- | --- | --- |
| M01 | 先选中用例，再用自然语言修改标题和预期结果 | 对话指向选中用例；正式资产在审阅前不变；确认后生成新 Revision；脑图显示更新节点。 |
| M02 | 不勾选，用例编号出现在修改指令中 | 自动匹配唯一目标；差异只包含该用例；拒绝后服务端变更状态结束，刷新页面不再弹出审阅，正式资产不变。 |
| M03 | 不勾选，使用“当前用例”修改 | 使用工作区当前可见用例作为目标；确认后仅该用例生成新 Revision，其它用例不变。 |
| M04 | 多条用例且指令没有可解析目标 | 明确要求选目标，不生成变更集，不修改正式资产。 |
| M05 | 生成差异与审阅期间 | 页面无脚本错误；脑图节点可见；改写状态与审核状态一致。 |

## 执行方式

在本地 API、Agent 和 Web 服务启动且演示账号可登录时运行：

```bash
CASEPILOT_E2E_BASE_URL=http://127.0.0.1:13000 \
CASEPILOT_E2E_API_URL=http://127.0.0.1:8100 \
pnpm --dir apps/web exec playwright test \
  e2e/ai-case-rewrite-recording.spec.ts \
  e2e/case-modification-acceptance.spec.ts
```

M01 由录屏验收用例覆盖；M02–M04 由用例修改验收用例覆盖；M05 贯穿 M01–M03。真实模型会参与差异生成，因此测试同时检查浏览器、API 返回和正式用例 Revision。

## 2026-09-17 执行结果

- Playwright 合并执行：4/4 通过，39.2 秒。
- API 对话意图与验收测试：31/31 通过；Web 构建和单元测试、类型检查、ESLint、Ruff 均通过。
- M01：确认应用后目标用例产生新 Revision，更新节点在脑图中可见。
- M02：按编号准确定位一条用例；拒绝后刷新页面不再出现待审阅变更，目标和非目标用例版本均不变。
- M03：不勾选时“当前用例”准确映射到当前可见用例，确认后只有目标用例版本增加。
- M04：无明确目标时要求用户选用例，正式资产保持不变。

验收中修复了 React Flow 节点在用例更新后丢失测量信息而隐藏、审阅“取消”未持久拒绝、工作区初始化时输入可能被清空，以及“把预期结果写得更明确”误判为知识问答的问题。
