# CasePilot V0.3 用例脑图与集合执行验收

> 验收日期：2026-07-26
> 前置基线：V0.2 用例管理与 QA 执行
> 验收范围：导航对齐、用例管理视觉、脑图新增/编辑、集合编辑和执行入口
> Figma：[脑图大画布与全屏入口](https://www.figma.com/design/fRnEKJHcshgCIa1CmYXbLx?node-id=110-25)

## 1. 用例管理页面

1. 使用 `demo@casepilot.local` 登录。
2. 确认“账号登录验收用例集”包含 `AUTH-001` 至 `AUTH-012` 共 12 条用例。
3. 确认品牌、用例管理、执行用例、头像和退出图标处于同一垂直中轴。
4. 确认集合标题、说明、用例统计和主要操作在常见 MacBook 宽度下不覆盖。
5. 确认脑图和资产列表不展示 QA 执行结果，结果仅在执行任务页面显示。

通过标准：

- 页面没有文字截断造成的关键信息缺失。
- 用例集合与用例资产无 QA 状态；每次 QA 执行结果独立保存。
- 页面重复刷新不会重复创建相同编号的示例用例。

## 2. 用例脑图

1. 点击“脑图”切换视图。
2. 确认结构为“用例集合 → 模块 → 用例”。
3. 使用左下角工具完成缩小、放大、适应画布和恢复 100%。
4. 点击右上角“全屏查看”，确认脑图占满视口并自动适配节点。
5. 按 `Esc` 或点击“退出全屏”，确认恢复原页面布局。
6. 拖动任意节点，确认画布不报错。
7. 点击集合节点的新增按钮，确认打开新建用例表单。
8. 点击模块节点的新增按钮，确认表单自动带入所属模块。
9. 点击用例节点的编辑按钮，确认打开当前用例及其最新 Revision。

通过标准：

- 脑图读取与列表相同的真实 REST API 数据。
- 脑图新增保存后，列表、脑图、详情和集合数量同步更新。
- 脑图编辑保存后产生新 Revision，不覆盖旧版本。

## 3. 用例集合编辑与执行

1. 点击“编辑集合”，修改名称或说明并保存。
2. 点击“创建用例集合”，填写名称与说明。
3. 验证“创建集合”留在用例管理页。
4. 验证“创建并进入执行”打开新建任务页并选中新集合。
5. 在已有集合点击“开始执行”，确认新建任务页自动选择当前集合。
6. 填写任务描述并创建，确认进入该任务的执行详情。

通过标准：

- 集合修改刷新后仍存在。
- 新集合进入任务创建页时，即使暂无用例也能看到明确空状态。
- 集合存在用例时，创建任务后执行队列加载全部当前用例。
- 执行结果、完成步骤、实际结果和缺陷引用继续写入 PostgreSQL。

## 4. 当前边界

- 脑图节点位置只在当前浏览器会话中调整，尚未写入数据库。
- V0.3 不恢复 AI 生成、AI 改写或文件解析入口。
- 用例集合关系调整、跨集合拖拽和批量节点操作进入后续开发顺序。
