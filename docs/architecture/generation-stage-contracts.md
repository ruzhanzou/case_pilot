# 用例生成阶段契约与验收口径

适用：确认测试说明后创建的新任务（`output_contract=case_batch_v2`）。历史任务继续按原契约重试，避免破坏已保存的阶段结果。

## 阶段责任

| 阶段 | 输入 | 输出 | 校验及发布规则 |
| --- | --- | --- | --- |
| 需求分析 | 用户需求、原始证据 | 测试对象、范围、规则、风险、假设 | 只有缺少测试对象才阻塞澄清；附件不构成系统指令 |
| 功能规划 | 需求与分段证据 | 功能、需求引用、模块 | 保留规则和来源，服务端稳定化编号 |
| 测试点规划 | 本批功能（最多 2 个） | 最多 12 个测试点 | 约束可引用的功能 ID，服务端合并去重 |
| 用例生成 V2 | 已确认测试点、原始证据、全局 slot | 每批最多 5 条内容 | slot 恰好覆盖输入集合；拒绝遗漏、重复、额外系统字段 |
| 独立来源核对 V2 | 本批用例与原始证据 | 每个 slot 的 supported / revise 判定 | supported 不返回正文；revise 返回同 slot 的完整修正及原因；缺失判定不可发布 |
| 服务端组装与质量校验 | 核对后的内容、确认规划 | 稳定编号、模块、优先级、类型、来源与覆盖矩阵 | 用例的目标明确、步骤可执行、预期可观察；通过后才保存本批预览 |
| 最终结果 | 所有已核对批次 | 可审核候选 | 完成整轮质量检查后可采纳；不自动写入正式资产 |

## 模型输出示例

用例生成只返回内容，避免反复输出数据库标识和来源全文：

```json
{"test_cases":[{"slot":1,"title":"有效凭据建立登录会话","preconditions":["已准备有效账号与凭据"],"steps":[{"action":"提交有效登录凭据","expected":"建立该账号的登录会话"}]}]}
```

核对通过时：

```json
{"reviews":[{"slot":1,"verdict":"supported","replacement":null,"reason":""}]}
```

核对不通过时：`verdict="revise"`，`reason` 说明问题，`replacement` 必须包含相同 slot 的完整内容。不能凭空添加跳转、HTTP 状态、提示文案或性能阈值；不确定规则不得作为确定的通过条件。

## 重试与恢复

- 新链路每个模型每次阶段最多尝试一次；非默认模型失败允许降级到默认模型。
- 新链路每次模型等待上限 90 秒（非默认模型保留更短的既有降级上限）；这不是整个任务的耗时承诺。
- 连接中断先重试原批次一次，仍失败则缩批，最小到单条停止。
- 格式错误、批次身份错误、核对错误、质量错误、模型超时会缩小当前批次，最小到单条；单条仍失败则停止并保留已核对的预览。
- 缩批重试不重复执行已完成的大批次；同一任务的相同阶段输入会复用已保存结果。错误的大批次在用户再次重试时仍可能尝试一次，随后复用已成功的小批次。
- 等待模型时不保持数据库事务。模型返回后重新检查取消状态，已取消的任务不能发布新结果。
- 原始模型响应保存在阶段记录中；用户可预览结果只包含已经核对并通过局部质量检查的用例。

## 进度语义

- `generated_count`：已通过来源核对和局部质量检查、保存为预览的用例数；不是模型刚返回的数量。
- `batch_start_index` / `batch_count`：当前正在处理的全局用例范围。
- `retry_attempt`：当前缩批分支的重试层级；界面明确说明重试并保留已核对结果。
- 生成阶段进度为 `floor(95 * generated_count / total_count)`；最终检查成功后才达到 100%。
- SSE 与轮询返回一致的批次元数据；刷新后使用服务端 `started_at` 继续计时。
- 本批完成事件发送计数，前端读取最新候选；不再在每次进度事件中发送累积用例全文。

## 已知边界

- 模型来源核对是辅助检查，不代表人工质量审核已通过。
- 新协议只用于已确认规划的工作台生成；兼容入口和历史任务保留旧协议。

## 批次并发

- V2 每个任务最多同时处理 2 批，每批最多 5 条；批内先生成、再独立核对。
- 哪批先核对通过就先发布，累积结果按全局 slot 排序。阶段缓存使用稳定偏移，不依赖批次完成顺序。
- 进度与预览串行提交，模型请求在锁和数据库事务外并行。
- 不可恢复错误会停止调度新批次，等待在途请求收尾后标记失败；取消状态在持久化前重新检查。
- `active_batches` 返回各在途批次的范围、生成或核对阶段及重试层级，界面分别展示。
- 并发不会消除供应商延迟、格式错误或重试；不能直接把并发数视为提速倍数。
