# 用例生成阶段契约与验收口径

适用：确认测试说明后创建的新任务（`output_contract=case_batch_v2`）。历史任务继续按原契约重试，避免破坏已保存的阶段结果。

## 阶段责任

| 阶段 | 输入 | 输出 | 校验及发布规则 |
| --- | --- | --- | --- |
| 需求分析 | 用户需求、原始证据 | 测试对象、范围、规则、风险、假设 | 只有缺少测试对象才阻塞澄清；附件不构成系统指令 |
| 功能规划 | 需求与分段证据 | 功能、需求引用、模块 | 保留规则和来源，服务端稳定化编号 |
| 测试点规划 | 本批功能（最多 2 个） | 最多 12 个测试点 | 约束可引用的功能 ID，服务端合并去重 |
| 用例生成 V2 | 已确认测试点、原始证据、全局 slot | 每批最多 5 条内容 | slot 恰好覆盖输入集合；拒绝遗漏、重复、额外系统字段 |
| 独立来源核对 V2 | 本批用例与原始证据 | 每个 slot 的 supported / revise 判定 | supported 不返回正文；revise 返回同 slot 的完整修正及原因；缺失判定不可发布 |
| 服务端组装与质量校验 | 核对后的内容、确认规划 | 稳定编号、模块、优先级、类型、来源与覆盖矩阵 | 用例的目标明确、步骤可执行、预期可观察；通过后才保存本批预览 |
| 最终结果 | 所有已核对批次 | 可审核候选 | 完成整轮质量检查后可采纳；不自动写入正式资产 |

## 模型输出示例

用例生成只返回内容，避免反复输出数据库标识和来源全文：

```json
{"test_cases":[{"slot":1,"title":"有效凭据建立登录会话","preconditions":["已准备有效账号与凭据"],"steps":[{"action":"提交有效登录凭据","expected":"建立该账号的登录会话"}]}]}
```

核对通过时：

```json
{"reviews":[{"slot":1,"verdict":"supported","replacement":null,"reason":""}]}
```

核对不通过时：`verdict="revise"`，`reason` 说明问题，`replacement` 必须包含相同 slot 的完整内容。不能凭空添加跳转、HTTP 状态、提示文案或性能阈值；不确定规则不得作为确定的通过条件。

## 重试与恢复

- 新链路每个模型每次阶段最多尝试一次；非默认模型失败允许降级到默认模型。
- 新链路每次模型等待上限 90 秒（非默认模型保留更短的既有降级上限）；这不是整个任务的耗时承诺。
- 连接中断先重试原批次一次，仍失败则缩批，最小到单条停止。
- 格式错误、批次身份错误、核对错误、质量错误、模型超时会缩小当前批次，最小到单条；单条仍失败则停止并保留已核对的预览。
- 缩批重试不重复执行已完成的大批次；同一任务的相同阶段输入会复用已保存结果。错误的大批次在用户再次重试时仍可能尝试一次，随后复用已成功的小批次。
- 等待模型时不保持数据库事务。模型返回后重新检查取消状态，已取消的任务不能发布新结果。
- 原始模型响应保存在阶段记录中；用户可预览结果只包含已经核对并通过局部质量检查的用例。

## 进度语义

- `generated_count`：已通过来源核对和局部质量检查、保存为预览的用例数；不是模型刚返回的数量。
- `batch_start_index` / `batch_count`：当前正在处理的全局用例范围。
- `retry_attempt`：当前缩批分支的重试层级；界面明确说明重试并保留已核对结果。
- 生成阶段进度为 `floor(95 * generated_count / total_count)`；最终检查成功后才达到 100%。
- SSE 与轮询返回一致的批次元数据；刷新后使用服务端 `started_at` 继续计时。
- 本批完成事件发送计数，前端读取最新候选；不再在每次进度事件中发送累积用例全文。

## 已知边界

- 模型来源核对是辅助检查，不代表人工质量审核已通过。
- 新协议只用于已确认规划的工作台生成；兼容入口和历史任务保留旧协议。

## 批次并发

- V2 每个任务最多同时处理 2 批，每批最多 5 条；批内先生成、再独立核对。
- 哪批先核对通过就先发布，累积结果按全局 slot 排序。阶段缓存使用稳定偏移，不依赖批次完成顺序。
- 进度与预览串行提交，模型请求在锁和数据库事务外并行。
- 不可恢复错误会停止调度新批次，等待在途请求收尾后标记失败；取消状态在持久化前重新检查。
- `active_batches` 返回各在途批次的范围、生成或核对阶段及重试层级，界面分别展示。
- 并发不会消除供应商延迟、格式错误或重试；不能直接把并发数视为提速倍数。

## 历史用例复用工作流（2026-10-15）

本节针对当前实现：用例批次采用本地结构校验与人工审核，`grounding_status=unverified`；
本文早期“每批独立模型核对”的描述不再代表当前默认 V2 链路。

### 策略与来源

需求分析同时输出 `fresh / regression / change` 与业务检索词，不额外调用路由模型。
全新生成不复用历史正文；回归与变更策略保留完整目标覆盖，再逐测试点决定新增、复用或修改。
Orchestrator 将“复用核心＋补充新版”保持为同一生成任务，不将其误拆为修改正式资产。

- Excel：继续支持 `.xlsx/.xls`，不增加截图输入。解析时识别中英文用例列，跨40行分段保留列映射。
  保留文件、Sheet、原始行号及原用例编号。标题、步骤、预期不完整或不符合现有候选结构的行仅作参考；
  不补造缺失预期，不直接复用多行合并的非标准用例。旧上传文件若尚无结构化行元数据，需重新上传才能直接复用。
- 用例资产：优先使用用户已选定范围；无显式范围时按业务词查询当前空间内未删除资产的当前版本，
  一次查询最多100条，不跨空间检索。查询采用标题与模块关键词匹配，目前不是资产向量检索。
- 两种来源统一为不可变快照。正式用例ID/版本及Excel来源定位进入计划，候选保留来源引用。
  复用表示把历史正文带入本次候选；采纳仍走已有候选入库，不自动更新原资产或建立执行计划引用。

### 决策与执行

每批最多12个测试点，最多30条完整候选来源、36,000字符来源预算、24,000字符规则证据预算，
最多3批并发比较，使用现有阶段缓存、一次瞬态重试与取消检查。
模型必须逐点返回且只能引用本批来源；缺点、重复点、虚构来源、操作与来源不一致的响应不能缓存。
规则证据超过预算时，不允许据此直接复用，降为生成审核候选。
每项记录比较与省略来源数，界面提示检索上限，不能把未选用的用例称作废弃。

复用正文由服务端原样复制，不让模型重写；同一历史用例覆盖多个测试点时仅输出一条候选。
修改仅向模型提供受影响点的原始快照和变更理由；新增沿用既有生成流程。
确认前检查需求、功能点、测试点快照，已修改的规划必须重新分析复用适用性。
生成端再次检查测试点快照，避免过期复用判断绕过确认流程。

### 真实工作状态

| 事件 | 展示词 | 触发时机 |
| --- | --- | --- |
| `knowledge.searching` | 正在搜索知识库… | 开始知识检索前 |
| `documents.reading` | 正在阅读参考资料… | 读取附件正文前 |
| `cases.searching` | 正在查询用例资产… | 解析历史资产范围前 |
| `reuse.comparing` | 正在分析变更与可复用用例… | 逐批复用比较期间 |

先持久化状态再发送SSE，刷新/轮询可以恢复；不得用定时轮播伪造过程。
界面显示策略、数量、理由、来源；长清单先展示30项，完整清单包含在测试说明下载中。

### 复用建议的用户消费（2026-10-15）

- 测试点节点显示“直接复用 / 基于历史修改 / 新增用例 / 不纳入本次”，支持按处理方式筛选。
- “查看依据与原文”只打开详情，不改变生成范围；详情展示建议理由、来源定位、原始前置条件、步骤和预期。
- 用户可选择“使用建议 / 重新生成，不复用正文 / 不纳入本次”。选择保存为测试说明新版本，刷新后保留；历史建议及来源保留供恢复和追溯。
- 确认时，后端先校验最新版本及选择合法性，裁剪用户指定范围和排除项，再将重新生成项转为 new 并移除其正文来源。全部排除时禁止提交；旧版本、未重分析的变更复用计划不能直接确认。
- 复用结果首先进入候选审阅，用户采纳后才纳入当前集合，历史资产不被修改。直接复用正文不调用生成模型。
- 查询历史资产仅用于本次生成时，合并为一个生成任务；明确要求单独展示查询结果时保留独立查询。
- 真实端到端验收入口：`apps/web/e2e/reuse-consumption.spec.ts`，通过 `CASEPILOT_REAL_ACCEPTANCE=1` 启用，必须指定独立 API/Web 服务。覆盖资产与 Excel 两种来源、选择保存与恢复、排除、真实生成、采纳入库及源资产版本不变。
