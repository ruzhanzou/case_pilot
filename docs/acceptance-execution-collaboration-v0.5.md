# CasePilot V0.5 执行任务历史与多人协作验收

> 验收日期：2026-07-27
> 前置基线：V0.4 用例资产与执行任务解耦
> 验收范围：空间级任务历史、任务创建、多人进度同步、并发冲突保护
> Figma：[新建任务必填校验](https://www.figma.com/design/fRnEKJHcshgCIa1CmYXbLx?node-id=111-25)

## 1. 任务历史入口

1. 使用示例账号登录。
2. 点击左侧“执行用例”。
3. 确认首先进入“执行任务”历史页，而不是直接打开某个集合或旧任务。
4. 从任一任务详情再次点击左侧“执行用例”。

通过标准：

- 显示当前空间的全部任务、执行中、已完成和参与成员统计。
- 每张任务卡显示任务描述、用例集合、状态、已执行进度、结果分布、参与成员和最后更新时间。
- 从详情再次点击主导航会返回任务历史。
- 页面每 5 秒同步一次任务进度。

## 2. 新建执行任务

1. 点击“新建执行任务”。
2. 选择用例集合。
3. 保持任务描述为空并点击“创建执行任务”。
4. 填写任务描述并再次创建。

通过标准：

- 不要求软件版本、构建号或测试环境。
- 任务描述为空时显示字段级提示并自动聚焦输入框，按钮不得静默无响应。
- 创建后冻结集合内每条用例的当前 Revision，并进入任务详情。
- 历史任务结果不会复制到新任务。

## 3. 多人协作执行

1. 两个属于同一空间的成员打开同一活动任务。
2. 成员 A 更新一条用例，成员 B 更新另一条用例。
3. 等待自动同步。

通过标准：

- 两位成员都可以更新任务，不限制为任务创建人。
- 任务页显示参与成员；队列与详情显示每条记录最后更新成员。
- 双方在 5 秒内看到最新进度和结果。
- 任务进度仅由当前任务的 Execution Record 派生。

## 4. 同记录并发冲突

1. 成员 A 与成员 B 同时打开同一条未执行记录。
2. 成员 A 先保存“通过”。
3. 成员 B 使用旧页面保存“不通过”。

通过标准：

- 成员 B 的请求返回 `409 execution_record_changed`。
- 系统不覆盖成员 A 的结果。
- 成员 B 页面加载最新记录并提示确认后重试。

## 5. 结束与历史恢复

1. 在活动任务中点击“结束任务”。
2. 返回任务历史并重新打开该任务。

通过标准：

- 任务状态更新为“已完成”，完成时间进入最后活动时间计算。
- 已完成任务只读，历史结果、步骤、实际结果、缺陷引用和更新成员保持不变。
- 同一集合可以继续新建其他任务，结果相互独立。
