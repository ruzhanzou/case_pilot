# 用例规划生成与修改优化计划

日期：2026-10-06。状态：待实施。

本次优化将结构化测试说明升级为可编辑的测试规划，在工作区先展示模块、功能、场景和测试点脑图，用户确认全部或部分范围后再生成用例。任务附件完整参与规划，用例生成与修改共享需求来源、规划节点和覆盖关系。

首个交付闭环是：上传需求资料 → 生成结构化说明和规划脑图 → 调整或选择分支 → 确认并生成候选用例 → 审阅入库。形成规划时不生成用例正文，也不写入正式用例。

## 当前基础与问题

| 当前基础 | 存在的问题 | 优化方向 |
| --- | --- | --- |
| 结构化测试说明已有版本、草稿、确认机制 | 确认说明后直接创建生成任务，说明阶段缺少可操作的脑图 | 在确认前生成并持久化规划树，确认时绑定规划版本和范围 |
| 上传附件保存为临时资料，对话记录文档和资料 ID | 生成上下文通过片段检索获取附件内容，可能遗漏需求 | 任务附件完整处理，知识库保留相关性检索 |
| 生成流程已有需求分析、功能点、测试点和覆盖矩阵 | 提示固定要求 2 至 4 个功能点、6 至 8 个测试点、8 至 10 条用例 | 按完整需求规模规划，按上下文预算分批生成 |
| 脑图支持多级模块路径及用例四段内容 | 功能、场景和测试点关系未直接构成脑图主干 | 使用持久化规划节点组织脑图，用例作为测试点下的结果 |
| 已有候选、修改差异、Revision 与版本冲突检查 | 资料变化和规划变化还需与用例影响建立关联 | 复用现有修改审阅机制，增加需求影响分析 |

实现核对入口：`apps/api/src/casepilot_api/conversations.py`、`apps/agent/src/casepilot_agent/tasks.py`、`apps/agent/src/casepilot_agent/pipeline.py`、`apps/agent/src/casepilot_agent/contracts.py`、`apps/web/components/case-mind-map.tsx`。开发应与当前工作区已有的范围选择、用例分析和工作区定位改动衔接。

## 产品流程

### 先形成规划

1. 根据用户要求、附件和选中范围识别本次任务，区分生成、补充、修改和仅分析。
2. 完整解析任务资料，记录成功、失败、缺失及版本信息。
3. 按章节提取需求条目，再整合跨章节关联，生成结构化说明和规划树。
4. 工作区自动显示规划脑图，说明与脑图引用同一份规划数据。显示规划节点数量，不显示为已生成用例数量。
5. 用户可编辑、移动、排除节点，也可通过对话补充场景；修改产生新规划版本。
6. 用户选择“确认规划并生成用例”或“为选中分支生成用例”。没有启动生成前，不生成步骤、预期结果等用例正文。

如果用户明确要求直接生成，可以在完成规划后自动进入生成；显式确认与自动继续采用相同的规划版本和范围快照，记录启动依据。

### 按规划生成

1. 固定本次规划版本、资料版本和选中节点，解析为服务端确定的测试点集合。
2. 按场景分批，携带当前测试点、对应原文、关联规则及必要的已有用例摘要。
3. 每完成一批就保存候选并推送进度，将候选挂到原有测试点下。
4. 检查规则覆盖、断言有效性、重复、矛盾和步骤可执行性。
5. 针对缺口补充生成；自动修复达到配置上限仍未解决时显示剩余问题。
6. 用户按分支或单条接受候选，复用现有入库与版本机制。

不规定所有需求都生成相同数量的用例。用户设置数量或成本预算时，优先生成核心范围，并列出未处理项，不把预算用尽显示为全部完成。

### 根据资料修改

1. 固定目标范围、已有用例 Revision 和新资料版本。
2. 对比需求条目，识别新增、变化、失效和未变化的规则；没有旧需求版本时明确这是对现有用例的符合性检查。
3. 沿需求与测试点关联定位用例，对缺少关联的历史用例做辅助检索并标记匹配不确定性。
4. 输出修改、新增、建议停用、无需变化四类结果，展示依据及字段差异。
5. 范围外的关联影响只作为建议列出，用户扩大范围后再执行。
6. 用户应用选中结果时检查最新版本，发生冲突则重新对比，不覆盖较新的编辑。

修改已有规划节点时不静默改写正式用例；受影响用例标为待同步。删除有用例关联的节点时，需选择迁移归属、仅排除本次范围或另行处理用例，保留历史追溯。

## 资料处理

| 资料角色 | 处理策略 |
| --- | --- |
| 本次任务依据 | 默认用于对话附件；完整处理所有可解析内容，保留定位与版本 |
| 补充参考 | 按相关性检索，补充背景，不自动扩大本次测试范围 |
| 历史版本 | 用于变更比较，不与当前版本无差别混用 |

短文档在可用上下文预算内全文读取；长文档逐章提取功能、角色、前置条件、业务规则、边界值、异常流程和依赖。章节处理记录应区分已处理、失败和待处理，不能静默截断。

需求条目须保留具体数值、单位、条件、例外与原文位置，生成时可读取完整关联段落。规划结构是导航索引，不代替原始依据。跨章节共用规则通过关联引用带入，避免只读当前分支而漏掉全局权限或状态约束。

扫描 PDF、原型图和表格中的规则需要相应的解析或视觉识别能力。首版至少能识别未提取出内容的页面并显示限制；未支持的图片内容不得标为已完整读取。视觉与复杂表格能力作为后续扩展，不阻塞文本附件闭环交付。

冲突资料保留双方来源；版本先后本身不代表优先级。能明确范围的分支继续处理，关键规则冲突只阻塞相关分支。

## 规划数据模型

以下为建议的逻辑模型，数据库命名在实施阶段统一。复用现有测试说明、候选和 Revision，不另建一套平行用例体系。

| 对象 | 关键内容 | 约束 |
| --- | --- | --- |
| 资料版本 | 文档 ID、内容指纹、角色、解析状态、章节与定位 | 已生成任务引用不可变的资料快照；不修改临时文件到期策略以掩盖引用失效 |
| 需求条目 | 稳定 ID、规则正文、来源引用、依赖、冲突、提取状态 | 每条有来源，模型补充的假设与文档事实分开标记 |
| 规划版本 | 工作区、说明版本、资料版本、父版本、状态 | 说明和脑图从同一份结构化数据派生，编辑时生成新版本 |
| 规划节点 | 稳定 ID、父 ID、类型、名称、顺序、需求关联、范围状态 | 节点类型为模块、功能、场景、测试点；禁止环和跨工作区归属 |
| 用例关联 | 测试点 ID、候选或正式用例 ID、主要归属 | 一个测试点可有多个用例，一条用例可关联多个测试点但只显示一个主要树归属 |
| 生成批次 | 规划版本、目标测试点、输入快照、状态、重试信息 | 幂等执行；重复提交和失败重试不生成重复候选 |

规划节点的范围状态与生成状态分开：范围为纳入、排除、待确认；生成进度按任务记录未开始、生成中、部分完成、失败、已完成。候选审阅状态也独立记录，避免“已生成”被误认为“已接受”。

节点改名和移动保留 ID；跨版本匹配优先使用稳定 ID 和来源关系，不依赖标题或路径。重新分析资料后先计算节点差异，保留用户编辑的名称、结构和排除决策。

## 脑图展示与操作

主干为“集合 → 模块 → 功能 → 场景 → 测试点 → 用例”。按业务复杂度使用层级，不人为填充空节点；测试点和用例一一对应且含义重复时可在视图合并，底层关联保留。

规划状态下测试点就是叶子节点，显示“待生成”；生成后在原节点下挂载候选用例。规则依据、前置条件、步骤和预期默认在详情侧栏查看，需要时展开当前用例。

| 阅读层次 | 默认展示 | 操作 |
| --- | --- | --- |
| 全局概览 | 模块、功能、场景及数量、缺口状态 | 展开层级、搜索、定位待处理项 |
| 分支浏览 | 当前功能下的场景、测试点和用例标题 | 选择分支生成、补充、修改或排除 |
| 用例精读 | 当前用例及四段详情 | 查看依据、编辑、对比与接受差异 |

复用现有全屏、搜索定位及工作区目标选择能力。增加路径导航、按层展开、真正折叠子树和局部分支聚焦。生成、刷新和应用修改后保留缩放、位置、选择和展开状态。

初始视图优先显示业务结构，不把全部用例详情缩成一屏。大规模数据采用按需加载与可见节点渲染；进度增量更新，避免每个批次完成后重排整棵树。

## 覆盖核对

分别记录三种核对结果，不合并成一个没有依据的总分：

1. 资料处理完整性：各章节是否已处理，是否存在解析失败或未支持内容。
2. 规划覆盖：纳入范围的需求条目是否关联测试点；排除项是否有原因。
3. 用例覆盖：测试点是否有候选或正式用例，对应规则是否被具体断言验证。

所有统计注明分母和范围，候选覆盖与已接受用例覆盖分开。需求条目被映射不等同于断言有效，更不等同于全文绝对无遗漏。没有需求资料时，只能给出现有用例结构与一致性检查。

## 实施阶段

### 阶段一 资料与规划基础

- [ ] 分离任务附件完整处理与知识库检索，增加资料角色、版本及章节处理记录。
- [ ] 建立需求条目、规划版本、规划节点与来源关联，设计迁移和接口契约。
- [ ] 拆分规划和用例生成任务；将功能点、测试点生成提前到结构化说明阶段。
- [ ] 取消固定功能点、测试点和用例总数量；实现按预算分批及未处理范围记录。
- [ ] 说明和脑图使用同一份规划结构，保留稳定节点 ID 和用户调整。

完成条件：只有规划任务时能返回完整规划树和来源，数据库中没有该任务产生的候选或正式用例。

### 阶段二 工作区规划脑图

- [ ] 在结构化说明审阅阶段展示脑图，支持节点详情和原文定位。
- [ ] 支持节点增删、移动、重命名、范围排除，以及对话驱动的结构调整。
- [ ] 增加全局、分支和详情阅读层次，支持按层展开及完整路径导航。
- [ ] 增加“确认规划并生成用例”和“为选中分支生成用例”，提交版本与节点范围。

完成条件：刷新后规划和编辑保留；确认前无用例正文；选择一个分支时服务端目标集合与界面一致。

### 阶段三 分支生成与覆盖检查

- [ ] 按规划版本和场景运行批次，增量保存并挂载候选。
- [ ] 支持停止、恢复、失败分支重试和重复请求幂等处理。
- [ ] 对照需求、测试点和断言检查缺口，限定补充修复次数及资源预算。
- [ ] 按分支或单条接受候选，保留来源、规划关联及既有 Revision 流程。
- [ ] 生成期间规划可形成新版本，当前任务仍使用原快照；旧版本结果标明来源并在应用前核对适用性。

完成条件：全量与选中分支生成均可完成审阅入库；重试不重复写入；界面保留定位；剩余缺口可见。

阶段一至三共同构成首个可交付版本，不把只有界面的静态脑图当作完整功能交付。

### 阶段四 修改与变更影响

- [ ] 资料新版本与需求条目进行比较，定位受影响规划节点和用例。
- [ ] 复用现有差异审阅，输出修改、新增、建议停用和无需变化结果。
- [ ] 对范围外影响、来源冲突和历史用例弱关联给出独立提示。
- [ ] 应用前验证用例与规划版本，支持冲突后重新生成差异。

完成条件：规则变化可定位相关边界场景；未选中用例不被修改；旧 Revision 与来源仍可追溯。

### 阶段五 大规模与复杂资料

- [ ] 基于实测完善脑图布局、按需加载和批量操作性能。
- [ ] 增加扫描文档、图片和复杂表格处理及质量反馈。
- [ ] 增加真实模型基准样本，记录需求提取遗漏、重复、耗时和用量。

完成条件：已支持的资料类型有端到端样本，性能有可复现结果，解析限制在产品中明确可见。

## 回归与验收

| 场景 | 验收标准 |
| --- | --- |
| 仅生成规划 | 说明和脑图都有模块、场景、测试点；无用例步骤与预期，无新候选或正式用例 |
| 长文档 | 超过原检索数量的资料中，首、中、末章节的人工标注规则均可定位到需求条目或明确失败状态 |
| 规则细节 | 数值、单位、例外条件及跨章节权限规则保留，并传入相关生成批次 |
| 用户编辑规划 | 改名、移动、排除后说明与脑图同步，刷新后保留，旧版本仍可追溯 |
| 单分支生成 | 只处理所选分支的测试点，其他分支维持未生成；统计与服务端范围一致 |
| 重试与停止 | 已完成批次保留，重试无重复候选，停止后不启动新批次；迟到结果按任务状态处理 |
| 版本并发 | 规划改版、用例人工编辑后，旧任务不覆盖新内容，差异应用产生明确冲突结果 |
| 修改资料 | 以阈值由 5 次改为 3 次为样本，核对阈值前、达到阈值和锁定后相关场景，展示逐字段差异 |
| 解析失败 | 无文本的扫描页、失败章节和不支持内容可见，不显示为全部已读取 |
| 覆盖统计 | 排除项、待生成项、候选和已接受用例分开计数，零分母不显示误导性百分比 |
| 脑图导航 | 规划树及 100、500、1000 条用例样本下，无重叠阻断；搜索、折叠、聚焦和刷新定位可用 |
| 旧数据兼容 | 无规划的历史集合仍可查看、编辑、生成和修改，不强制重建用例 |

API 测试覆盖权限、版本、范围、幂等和迁移；Agent 测试覆盖附件完整处理、批次输入及修复边界；浏览器测试覆盖规划预览、分支生成、增量挂载和差异应用。真实模型评估与 Mock 流程验证分开报告，不能用 Mock 通过证明需求提取准确。

性能验收使用固定浏览器、设备、视口和数据集，记录首次展示、分支展开、搜索定位及交互延迟；具体阈值在取得当前基线后确定。

## 兼容与发布

采用增量数据迁移和功能开关，先对新工作区启用。旧集合继续按现有模块结构展示；用户选择重建规划时创建草稿并关联原用例，不自动改写标题、编号或 Revision。

新接口增加规划版本和节点范围，兼容旧客户端的确认接口；服务端对旧请求生成明确范围快照。关闭新功能开关时仍能读取新数据并维护已有用例，不通过删除规划数据回退。

需求来源应保存生成所需的引用快照和指纹，明确原附件过期或删除后的查看状态，并遵守资料删除策略。不得因临时附件清理导致用例来源被错误指向新资料。

本计划的实施边界为生成、修改、资料依据和工作区脑图。执行调度、自动化脚本生成及外部平台同步不纳入本轮。
